# Results: 2026-10-25

Re-run of the PERF-001 experiment to check the fix in
[taskflow-under-test#18](https://github.com/VincentJerico/taskflow-under-test/pull/18) (async
`crypto.scrypt` plus a rate limit on `/api/auth/*`). Only `experiments/auth-contention.js` was
run.

## Environment

|                   |                                                                                          |
| ----------------- | ---------------------------------------------------------------------------------------- |
| System under test | TaskFlow `8b0d564` (before) and `bea4cc3` (after, PR #18), fresh database per run        |
| Runtime           | Node 24.22.0 (CI uses Node 22)                                                           |
| Load generator    | k6 v2.3.0                                                                                |
| Machine           | Apple M5 Pro, 15 cores, 24 GB RAM, macOS 27.0.1. k6 and TaskFlow ran on the same machine |

compare with the [2026-10-24 results](RESULTS-2026-10-24.md), which came from a 4 vCPU Linux VM.

## Rate limit and the suite

With the fix and TaskFlow's default limit (20 auth requests per client per minute),
`scenarios/load.js` failed in `setup()`: `could not sign in k6-…-10`, k6 exit code 107. Setup
signs in 20 users (40 auth requests) from one IP. `scripts/start-sut.sh` now starts TaskFlow with
`AUTH_RATE_LIMIT=0`. With that, the load test passed: 2,339 requests, 0% failed, 4,274 of 4,274
checks. The gate self-test still exits with code 99 (pass).
