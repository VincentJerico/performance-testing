# Results: 2026-10-24

## Environment

|                   |                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------- |
| System under test | TaskFlow `8b0d564` (Node 22.23.4, Express, better-sqlite3, fresh database per run) |
| Load generator    | k6 v2.3.0                                                                          |
| Machine           | Linux arm64 VM, 4 vCPU, 4 GB RAM. k6 and TaskFlow ran on the **same** machine      |
| Network           | localhost, so the numbers are server time without real network latency             |
| Think time        | 1 s between steps (0 s in the breakpoint test)                                     |

Running the load generator on the same machine is a known limitation: past a few thousand
requests per second, k6 and the server compete for the same CPUs. It's called out below where it
affects a result.

## Scenarios

All per-endpoint budgets are p95 (see [lib/slo.js](../../lib/slo.js)). Stress and spike use 3x
budgets, because their goal is to observe degradation.

## Experiment: auth contention
